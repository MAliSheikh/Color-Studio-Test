# Task 4 — Shopify Product Review App

A minimal but fully functional Shopify embedded app that collects and displays product reviews, with an AI-generated summary powered by the Groq API.

---

## What's Built

| Feature | Details |
|---------|---------|
| **Admin Dashboard** | Merchant-facing review dashboard, embeddable in Shopify Admin via App Page |
| **Storefront Widget** | Rendered on product pages via a Theme App Extension (App Block) |
| **Review Submission** | Form accepting customer name, star rating (1–5), and review text |
| **Database** | SQLite locally; plug in the PostgreSQL `DATABASE_URL` to use the Task 1 schema |
| **AI Summary** | One-sentence summary generated by Groq API (Llama-3.3-70b) |
| **REST API** | `GET /api/reviews?sku=` and `POST /api/reviews` |

## Quick Start (Local Dev)

### 1. Install Dependencies

This project uses the root `uv` workspace. From the repo root:

```bash
uv sync
```

### 2. Configure Environment

The app reads from the root `.env` file automatically. Make sure `GROQ_API_KEY` is set:

```env
GROQ_API_KEY=gsk_...your_key...
DATABASE_URL=sqlite:///./task4_reviews.db   # default — no config needed
```

To use PostgreSQL (Task 1 schema):
```env
DATABASE_URL=postgresql://user:pass@localhost:5432/colorstudio
```
The `reviews` table is already defined in `Task 1/task_1a_schema_design/schema.sql`.

### 3. Run the Server

From the **repo root**:
```bash
uv run uvicorn "Task 4.app.main:app" --reload --port 8000
```

Or from `Task 4/app/`:
```bash
uvicorn main:app --reload --port 8000
```

The server starts on **http://localhost:8000**

### 4. Test the App

| URL | Purpose |
|-----|---------|
| `http://localhost:8000/` | Landing page |
| `http://localhost:8000/admin` | Merchant dashboard |
| `http://localhost:8000/widget?sku=SKU-001` | Storefront widget preview |
| `http://localhost:8000/api/reviews?sku=SKU-001` | JSON API |
| `http://localhost:8000/docs` | Interactive API docs (Swagger UI) |

**Submit a test review via curl:**
```bash
curl -X POST http://localhost:8000/api/reviews \
  -H "Content-Type: application/json" \
  -d '{"product_sku":"SKU-001","customer_name":"Jane Doe","rating":5,"review_text":"Absolutely love this product! The texture is perfect."}'
```

## Shopify Installation on a Development Store

### Prerequisites
- [Shopify Partner account](https://partners.shopify.com) (free)
- A development store created in your Partner Dashboard
- [Shopify CLI](https://shopify.dev/docs/api/shopify-cli) installed (Node.js 18+ required)
- [ngrok](https://ngrok.com) or similar tunnel to expose localhost

### Step 1 — Create the App in Partner Dashboard

1. Go to **Partners → Apps → Create app → Create app manually**
2. Note your **API key** and **API secret key**
3. Add `http://localhost:8000/auth/callback` to **Allowed redirection URLs**

### Step 2 — Configure `shopify.app.toml`

Edit `Task 4/shopify.app.toml`:
```toml
client_id = "YOUR_API_KEY"
dev_store_url = "your-store.myshopify.com"
```

### Step 3 — Expose localhost with ngrok

```bash
ngrok http 8000
```

Copy the `https://xxxxx.ngrok.io` URL — you'll need it for the App Block setting.

### Step 4 — Install the Theme App Extension (Manual Method)

Since the backend is Python (not Node.js), you can install the App Block manually:

1. Log into your Shopify Admin → **Online Store → Themes**
2. Click **Actions → Edit code** on your active theme
3. Navigate to `sections/` or create a new `snippets/product-reviews.liquid`
4. Copy the contents of `extensions/product-reviews/blocks/product-reviews.liquid`
5. In the theme editor, add the snippet to your product page template

**Or use the Shopify CLI** (if Node.js 18+ available):
```bash
cd "Task 4"
shopify app dev
```
This will push the extension and open a preview link in your browser.

### Step 5 — Configure the App Block

1. In Shopify Admin → **Online Store → Themes → Customize**
2. Navigate to **Products → Default product**
3. Click **Add block** → find **Product Reviews**
4. Set **Review App URL** to your ngrok URL (e.g. `https://xxxxx.ngrok.io`)
5. Toggle **Show AI Summary** on
6. **Save**

The widget will now appear on all product pages and will:
- Fetch and display reviews for the current product's SKU
- Show the AI-generated summary
- Allow customers to submit new reviews

## API Reference

### `GET /api/reviews?sku=<sku>`

Returns all reviews and AI summary for a product SKU.

```json
{
  "sku": "SKU-001",
  "total": 3,
  "average_rating": 4.3,
  "ai_summary": "Most reviewers praise the rich texture and lasting scent, though a few find the packaging could be sturdier.",
  "reviews": [
    {
      "id": "uuid",
      "product_sku": "SKU-001",
      "customer_name": "Jane Doe",
      "rating": 5,
      "review_text": "Love it!",
      "created_at": "2025-05-09T12:00:00+00:00"
    }
  ]
}
```

### `POST /api/reviews`

Submit a new review.

**Request body (JSON):**
```json
{
  "product_sku": "SKU-001",
  "customer_name": "Jane Doe",
  "rating": 5,
  "review_text": "Absolutely love this product!"
}
```

**Response (201):**
```json
{ "success": true, "review": { ... } }
```

### `GET /api/skus`

Returns all SKUs that have at least one review.

## Database Schema

The `reviews` table matches the Task 1 PostgreSQL schema exactly:

```sql
CREATE TABLE reviews (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    product_sku VARCHAR(100) NOT NULL,
    customer_name VARCHAR(255) NOT NULL,
    rating INTEGER NOT NULL CHECK (rating >= 1 AND rating <= 5),
    review_text TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_reviews_product_sku ON reviews(product_sku);
```

Locally, SQLite is used with a string UUID (generated in Python) for zero-config development.

## AI Summary

The AI summary is generated by calling the Groq API with the `llama-3.3-70b-versatile` model. The prompt instructs the model to produce exactly one concise sentence summarising overall customer sentiment, highlighting what customers praise or criticise.

**Example output:**
> "Buyers consistently praise the smooth texture and long-lasting formula, with minor notes about the packaging quality."

If `GROQ_API_KEY` is not set, summaries are silently skipped and the widget/dashboard remains fully functional.

## Design Decisions

- **Python/FastAPI over Node.js** — Consistent with the rest of the project (Tasks 2 & 3 also use FastAPI). The Liquid extension is framework-agnostic.
- **SQLite default** — Zero-config for evaluators; switch to PostgreSQL by changing `DATABASE_URL`.
- **CORS enabled** — The App Block fetches from the FastAPI server cross-origin (Shopify storefront domain ≠ app server domain).
- **No OAuth flow implemented** — A full OAuth handshake is beyond the scope; the admin dashboard is accessible directly. For production, HMAC verification middleware is stubbed in `main.py`.
