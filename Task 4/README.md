# Task 4 — Shopify Product Review App

A minimal but fully functional Shopify embedded app that collects and displays product reviews, with an AI‑generated summary powered by the Groq API.

## What's Built

| Feature | Details |
|---------|---------|
| **Admin Dashboard** | Merchant‑facing review dashboard, embeddable in Shopify Admin via App Page |
| **Storefront Widget** | Rendered on product pages via a Theme App Extension (App Block) |
| **Review Submission** | Form accepting customer name, star rating (1–5), and review text |
| **Database** | SQLite locally; plug in the PostgreSQL `DATABASE_URL` to use the Task 1 schema |
| **AI Summary** | One‑sentence summary generated by Groq API (Llama‑3.3‑70b) |
| **REST API** | `GET /api/reviews?sku=` and `POST /api/reviews` |

## Quick Start (Local Dev)

### 1. Install Dependencies

This project uses the root `uv` workspace. From the repo root:

```bash
uv sync
```

### 2. Configure Environment

The app reads from the root `.env` file automatically. Make sure `GROQ_API_KEY` is set:

```env
GROQ_API_KEY=gsk_...your_key...
DATABASE_URL=sqlite:///./task4_reviews.db   # default — no config needed
```

To use PostgreSQL (Task 1 schema):
```env
DATABASE_URL=postgresql://user:pass@localhost:5432/colorstudio
```
The `reviews` table is already defined in `Task 1/task_1a_schema_design/schema.sql`.

### 3. Run the Server

From the **repo root**:
```bash
uv run uvicorn "Task 4.app.main:app" --reload --port 8000
```

Or from `Task 4/app/`:
```bash
uvicorn main:app --reload --port 8000
```

The server starts on **http://localhost:8000**

### 4. Test the App

| URL | Purpose |
|-----|---------|
| `http://localhost:8000/` | Landing page |
| `http://localhost:8000/admin` | Merchant dashboard |
| `http://localhost:8000/widget?sku=SKU-001` | Storefront widget preview |
| `http://localhost:8000/api/reviews?sku=SKU-001` | JSON API |
| `http://localhost:8000/docs` | Interactive API docs (Swagger UI) |

**Submit a test review via curl:**
```bash
curl -X POST http://localhost:8000/api/reviews \
  -H "Content-Type: application/json" \
  -d '{"product_sku":"SKU-001","customer_name":"Jane Doe","rating":5,"review_text":"Absolutely love this product! The texture is perfect."}'
```

## API Reference

### `GET /api/reviews?sku=<sku>`

Returns all reviews and AI summary for a product SKU.

```json
{
  "sku": "SKU-001",
  "total": 3,
  "average_rating": 4.3,
  "ai_summary": "Most reviewers praise the rich texture and lasting scent, though a few find the packaging could be sturdier.",
  "reviews": [
    {
      "id": "uuid",
      "product_sku": "SKU-001",
      "customer_name": "Jane Doe",
      "rating": 5,
      "review_text": "Love it!",
      "created_at": "2025-05-09T12:00:00+00:00"
    }
  ]
}
```

### `POST /api/reviews`

Submit a new review.

**Request body (JSON):**
```json
{
  "product_sku": "SKU-001",
  "customer_name": "Jane Doe",
  "rating": 5,
  "review_text": "Absolutely love this product!"
}
```

**Response (201):**
```json
{ "success": true, "review": { ... } }
```

### `GET /api/skus`

Returns all SKUs that have at least one review.

## Database Schema

The `reviews` table matches the Task 1 PostgreSQL schema exactly:

```sql
CREATE TABLE reviews (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    product_sku VARCHAR(100) NOT NULL,
    customer_name VARCHAR(255) NOT NULL,
    rating INTEGER NOT NULL CHECK (rating >= 1 AND rating <= 5),
    review_text TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_reviews_product_sku ON reviews(product_sku);
```

Locally, SQLite is used with a string UUID (generated in Python) for zero-config development.

## AI Summary

The AI summary is generated by calling the Groq API with the `llama-3.3-70b-versatile` model. The prompt instructs the model to produce exactly one concise sentence summarising overall customer sentiment, highlighting what customers praise or criticise.

**Example output:**
> "Buyers consistently praise the smooth texture and long-lasting formula, with minor notes about the packaging quality."

If `GROQ_API_KEY` is not set, summaries are silently skipped and the widget/dashboard remains fully functional.

## Design Decisions

- Python/FastAPI chosen for consistency with other tasks.
- SQLite default for zero‑config development; PostgreSQL can be used via `DATABASE_URL`.
- CORS enabled for the App Block.
- No OAuth flow – admin dashboard is directly accessible (production would add HMAC verification).
